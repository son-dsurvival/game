# Domain Docs

This is a single-context repository.

Before making changes:

1. Read root `CONTEXT.md`.
2. Read applicable decisions under `docs/adr/`.
3. Use canonical glossary terms in tickets, tests, and implementation.
4. Surface conflicts with existing ADRs instead of silently overriding them.
5. If domain documentation is absent, proceed silently; create it lazily through domain modeling when a term or decision is resolved.
